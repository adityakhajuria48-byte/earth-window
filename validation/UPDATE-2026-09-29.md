# Website update — 29 September 2026

## User-visible changes

- Removed Before A / After B buttons, comparison date fields, swipe controls and their controller. Single-band previews still display in 2D or 3D; terrain controls and dated daily basemaps remain.
- Archive pages appear as they arrive instead of waiting for all pagination of that archive. Successful query responses are cached in browser memory for five minutes (42 entries maximum). Cloud, resolution and requested-time ranking changes reuse the same network query when geographic/date ranges match. Errors are not cached. Cache reuse is labelled in results. Reload clears it.
- Progressive screen/map updates are batched at 150 ms rather than rebuilding on every simultaneous response. All 21 collections remain searched, with the existing page limits and failure reporting. No claim of measured live-provider latency or guaranteed faster provider responses is made.
- The GeoTIFF export panel defaults to Mask to uploaded boundary for shapefile searches. Uncheck it for a rectangle. Holes and multipart polygons are supported. The rectangle fields still restrict the output window. Previews remain rectangular.
- Python preserves valid native pixel values, CRS, grid, calibration and source masks. Exterior/hole pixels are set to no-data (or zero when the source has no no-data value) and excluded by an internal TIFF validity mask. Rasterization uses Rasterio's default pixel-centre rule; no fractional-pixel clipping is claimed. AREA_MASK and PROCESSING tags document it.

## Safeguards

Requests are capped at 1 MiB in both the gateway and Python, 500 polygons, 20,000 vertices, finite WGS84 coordinates and closed rings. Invalid/overlapping topology is rejected before reading the source pixel window. Existing identity, origin, provider allowlist, 2-degree bounds, 4-million-pixel, 64-MiB transfer and 90-second processing limits remain. No new credentials or dependencies.

- 45 Python tests pass.
